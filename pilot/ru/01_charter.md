# Хартия пилотного проекта Resilix
Версия: 0.1 (Пилот)
Статус: Черновик для внешнего пилотного обзора
Аудитория: HR-директора, COO, консультанты по организационному развитию
Продукт: Resilix — Система обзора доказательств организационной устойчивости
---
# Назначение пилотного проекта
Данный пилотный проект предназначен для оценки того, насколько интерфейс и логика Resilix воспринимаются как понятные, полезные и эпистемически корректные в корпоративной среде.

Цель пилота — проверить:
* насколько пользователи понимают ограничения системы;
* воспринимается ли происхождение сигналов как прозрачное и прослеживаемое;
* помогают ли результаты выявлять наблюдаемые организационные паттерны;
* вызывает ли подход доверие без использования завышенных технологических заявлений;
* представляет ли ценность калибровка с внутренними организационными сигналами.

Resilix не предназначен для автоматизированного принятия решений. Пилот оценивает полезность подхода «детерминированная логика + прослеживаемый вывод» для организационного анализа.

⸻

# Что представляет собой Resilix
Resilix — это система на основе фиксированных правил для анализа организационной устойчивости, использующая:
* публичные ESG-сигналы;
* сигналы рынка труда;
* управленческие и корпоративные коммуникации;
* структурные паттерны зависимости;
* дополнительные внутренние сигналы (только при калибровке).

Система использует:
* детерминированную логику вывода;
* фиксированные правила интерпретации;
* прослеживаемый вывод;
* происхождение сигналов для каждого производного вывода.

Каждый производный вывод ссылается на:
- `triggered_by[]`
- `derived_from[]`
- цепочки происхождения сигналов
- ограничения глубины вывода

Система предназначена для ограничения неподдерживаемой интерпретации при повышении организационной прослеживаемости.

⸻

# Что Resilix НЕ делает
Resilix НЕ является:
* системой предсказаний;
* системой стратегического прогнозирования;
* системой диагностики персонала;
* системой профилирования сотрудников;
* системой оценки личности;
* платформой «на базе ИИ»;
* инструментом скрытого мониторинга сотрудников.

Resilix НЕ:
* вычисляет вероятность событий;
* определяет «истинное состояние» организации;
* строит психологические профили;
* генерирует автономные выводы без происхождения сигналов;
* заменяет управленческое решение.

Интерпретации в интерфейсе следует рассматривать как структурированный обзор наблюдаемых организационных паттернов, а не как окончательные заключения.

⸻

# Допустимые сценарии использования
Пилотный проект допускает использование Resilix для:
* обзора организационной устойчивости;
* выявления наблюдаемой концентрации зависимости;
* анализа координационных разрывов;
* обсуждения операционной устойчивости;
* подготовки к внутренней калибровке;
* структурирования управленческих обсуждений;
* сопоставления внешних и внутренних сигналов.

Допустимо использование результатов как вспомогательного материала для:
* HR-директоров;
* COO;
* подразделений организационного развития;
* руководящих комитетов (steering committee);
* внутренних сессий по трансформации/воркшопов.

⸻

# Запрещённые сценарии использования
Resilix запрещено использовать для:
* оценки отдельных сотрудников;
* кадровых решений;
* увольнений;
* оценки эффективности персонала;
* психологических заключений;
* поведенческого профилирования;
* скрытого наблюдения;
* расчёта «надёжности» сотрудников;
* автоматизированного принятия решений.

Система поддерживает только агрегированный анализ.
Минимальный размер внутренней выборки для калибровки: n ≥ 5.

⸻

# Происхождение сигналов и покрытие сигналов
Resilix использует концепцию Происхождение сигналов.

Это означает, что:
* каждый вывод связан с конкретными сигналами;
* выводы должны быть проверяемыми;
* пользователь может проследить происхождение структурных выводов.

В рамках пилота большинство демонстраций используют:
* публичные ESG-материалы;
* публичные вакансии;
* корпоративные сообщения;
* открытые организационные сигналы.

В интерфейсе это обозначается как:
`Покрытие сигналов: частичное (только публичные сигналы)`

Это означает:
* система видит только внешне наблюдаемые сигналы;
* часть внутренних процессов недоступна;
* выводы ограничены наблюдаемыми данными;
* дополнительные внутренние сигналы могут изменить интерпретацию.

⸻

# Интерпретационный слой (недиагностический)
Resilix может отображать элементы vMEME и Spiral Dynamics (Спиральная динамика).

Важно:
* это интерпретационный слой (недиагностический);
* это НЕ научное измерение личности;
* это НЕ классификация сотрудников;
* это НЕ психологический инструмент.

Использование цветов и распределений отражает относительное присутствие наблюдаемых организационных паттернов.
Это концептуальная карта интерпретации, а не объективное измерение организации.

⸻

# Конфиденциальность и защита данных
Внутренняя калибровка выполняется с соблюдением следующих принципов:
* только агрегированный анализ;
* изоляция пространства данных (namespace isolation) между организациями;
* отсутствие индивидуальных профилей;
* конфиденциальность внутренних сигналов;
* отсутствие передачи данных третьим сторонам;
* ограничение глубины вывода;
* прослеживаемый вывод для производных объектов.

Resilix не предназначен для хранения персональных профилей сотрудников.

⸻

# Этапы пилотного проекта
## Этап 1 — Демонстрационный обзор
* Ознакомление с интерфейсом;
* Анализ демонстрационного набора сигналов;
* Обсуждение ограничений и происхождения сигналов.

## Этап 2 — Сбор обратной связи
* Заполнение структурированного шаблона обратной связи;
* Фиксация точек непонимания;
* Проверка доверия к происхождению сигналов.

## Этап 3 — Калибровочная дискуссия (опционально)
* Обсуждение внутренних организационных сигналов;
* Проверка согласованности между внешними и внутренними сигналами;
* Определение применимости для расширения пилота.

⸻

# Критерии успешности пилота
Пилот считается успешным, если участники:
* понимают ограничения системы;
* воспринимают происхождение сигналов как прозрачное;
* интерпретируют результаты без ожиданий «предсказаний»;
* используют результаты как основу для обсуждения организационной устойчивости;
* проявляют интерес к калибровке с внутренними сигналами.

Критически важно отсутствие следующих реакций:
* ожидание автоматических прогнозов;
* ожидание психологической диагностики;
* восприятие системы как «чёрного ящика»;
* опасения скрытого профилирования сотрудников.

⸻

# Примечание переводчика
* Термин «Interpretive Overlay» переведён как «интерпретационный слой (недиагностический)» для сохранения управленческого смысла и исключения диагностических ассоциаций.
* Термин «aggregate-only» переведён как «только агрегированный анализ» вместо буквальной кальки для лучшей читаемости в корпоративной среде Казахстана/России.
* Термин «steering committee» сохранён частично в английской форме как распространённый корпоративный термин с пояснением.
`constrain intelligence, expand traceability`
